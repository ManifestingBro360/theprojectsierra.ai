Why a clean merge can still break main

Guide, 22 November 2026

A semantic merge conflict is when two changes merge with no text conflict, each passed its own tests, and the combined result is broken. Git cannot see it, because Git compares lines, not meaning.

The smallest example

branch A changes a function
- export function toCents(amount) {
+ export function toCents(amount, mode) {
branch B, in another file, adds a call
+ const fee = toCents(order.fee);

The branches touch different files, so Git merges them cleanly. A updated every caller that existed when it ran its tests. B's call did not exist yet. B tested against the old toCents. After both land, B's call passes one argument to a function that needs two.

Common shapes

  • A function's signature changes while a new caller is written elsewhere.
  • A function is removed or renamed while new code starts using it.
  • A value's meaning changes (cents to units, seconds to milliseconds) and a new reader assumes the old one.
  • A configuration key is renamed in one branch and read in another.

Why agents cause more of them

People working in the same area usually mention it to each other. Agents in separate worktrees do not know the others exist. They also work fast and in parallel, so more changes overlap in time, and they read the code once at the start and trust what they read.

Four ways to catch them

MethodWhen it catches itWhat it needs
CI on main after mergeAfter main is already brokenA test that covers the new call
Merge queueAt merge, before main movesA test that covers the new call
A typed language and a full build in the queueAt mergeThe break to be a type error
Tracking who reads and calls whatWhile both are still workingA record of each agent's reads and writes

The first three all act at merge time and depend on a test or a type check noticing. The last is what Canopy does: when a signature changes in one worktree, every other worktree that read it, calls it, or is changing something that depends on it is told in its agent's next tool call. If the call is still stale at landing, the landing is refused whether or not a test covers it.

What this approach misses

Canopy's code graph is built by pattern matching on JavaScript, TypeScript, Python and Go. It does not follow dynamic dispatch, re-exports, or dependencies that are not code references, such as a changed database column. A merge queue with good tests remains worth having.
